## Как читать этот план

- **Волны.** Задачи идут волнами. Каждая волна заканчивается результатом, который можно показать. Если время кончилось — демо обрывается на последней закрытой волне, остальное показываем как план.
- **Швы между задачами.** Задача K1 фиксирует контракт API и внутренние интерфейсы сервисов. После неё бэкенд, AI и фронт работают параллельно: фронт — с моком Prism, бэкенд — с заглушками сервисов, которые ещё не готовы.

- **Оценки** — часы работы одного человека со своим ИИ-агентом, без ожидания ревью.
- **Правила** — в `AGENTS.md`: одна задача — одна ветка — один PR; на каждый эндпоинт с данными пользователя — тест «чужой получает 404».

## Сквозные решения

Их фиксирует K1; оспорить можно там же, до начала волны 1.

1. **AI работает асинхронно.** Сообщение пользователя ставит задачу в Celery; у обращения есть поле `ai_state` (`idle`, `thinking`, `failed`); фронт опрашивает обращение, пока `thinking`. Вызов модели не держит HTTP-запрос.
2. **Ответ модели — всегда JSON по схеме.** Схему проверяем сериализаторами DRF, новая зависимость не нужна. Не прошёл проверку — один повтор, затем `ai_state = failed` и понятное сообщение пользователю.
3. **Цитату-источник проверяет код.** Факт принимается, только если его цитата дословно есть в сообщении или документе. Иначе поле получает статус «не найдено». Это главная защита от выдумок модели.
4. **Сроки, суммы и нормы — не от модели.** Сроки и суммы считает код по датам карточки; нормы берутся из библиотеки (A3). Модель пишет только связный текст вокруг них; ссылки на статьи вне библиотеки отклоняются проверкой.
5. **Персональные данные хранятся отдельно от карточки.** ФИО, адрес и контакты лежат в отдельной модели; в сериализаторах очереди и пула их нет физически, а не «скрыто флагом».
6. **Модератор работает через админку Django.** Отдельный интерфейс модератора не делаем.
7. **Деньги — заглушка.** Модель `Hold` и сервис `hold / release / refund` с тем же интерфейсом, что будет у платёжного провайдера. Реальных платежей в прототипе нет.
8. **Цены и сроки — в настройках.** Цена претензии, доля проверяющего, комиссия, таймаут проверки 4 часа, окно предложений 48 часов, приёмка 3 дня — переменные окружения с умолчаниями.
9. **Тесты и CI — только на моке LLM.** Мок детерминированный и покрывает сценарий Ани из `docs/mvp.md`.

### A1. LLM-клиент: мок и OpenAI-совместимый провайдер

- **Зачем:** все AI-задачи ходят в модель через один клиент; тесты и CI обязаны работать без сети.
- **Что сделать:**
  - Приложение `llm`: функция `complete_json(task, payload, schema)` → проверенный словарь или исключение.

  - Провайдер для OpenAI-совместимого API: адрес, ключ и модель из окружения; таймаут; один повтор при сбое или невалидном JSON.
  - Проверка ответа по схеме сериализатором DRF.
  - Пользовательский текст и документы передаются модели как данные в отдельном блоке, а не как инструкции.
  - В логи — только имя задачи, длительность и исход; без текста пользователя.
- **Контракт:** не меняется.
- **Готово, когда:**
  - [ ] с `LLM_PROVIDER=mock` всё работает без сети и ключей

  - [ ] в логах нет текста пользователя
